## 排查与取证

- 本技能未覆盖的部分遵循 `diagnosing-bugs`
- 优先快速、低成本的排查；代码问题按「代码位置 → 近期 Git 变更 → 现场日志」定位
- 先确认现象和背景，再查官方文档、ctx7 对应版本文档与社区同类问题，避免从零重复调查

## 方案选择

- 根因确认后，用对应版本文档和同类 issue 复核方案，核对实际运行版本；现有版本或原生机制已覆盖根因时，优先保持配置，不新增工具或流程
- 优先社区已验证的简单方案，其次选择有根因依据、可靠且最简单的方案；无法推荐时，列出可行选项供用户选择
- 执行前说明风险与回退方式，与用户确认后再执行

## 用户反馈

- 先说当前是否已修复、是否需要变更，再给最推荐的动作和理由
- 用证据解释根因；有日志时间点时，说明当时什么操作触发了问题，只展开会影响决策的证据与风险
- 必要修复、一次性收尾、可选加固分开说明

## 执行约束

- 长耗时命令设置合理超时，输出明确的成功或失败信号，用短时、有界轮询替代无限等待
- 遇到网络 IP 以 `198` 开头时，按本地 TUN 代理处理，停止本地网络测试与验证并告知用户

## 复现实验

当需要做复现, 构建实验时, 应该

- 优先轻量实验, 只有必须用户来操作的地方才让用户接手
- 任何需要`涉及大量构建或者大量下载操作`必须经过用户同意
- 所有实验和产物限定在当前项目范围内
- 实验成功后和用户确认并告知`所有临时产物`和`所有临时操作`, 并给出`清理步骤`

## 记录与收尾

- 棘手问题在项目根目录创建 `DISCOVERY.md`，持续记录重要发现、失败和成功的尝试、错误假设与经验
- 按时间线追加，越新越靠后，阅读时从后往前
- 收尾前阅读 `project-memory`，从记录中提取可复用结论，舍弃流水账；优先沿用项目已有记录位置，没有时向用户建议，展示摘要并经用户同意后存入
- 成功解决并经用户确认后，清理临时文件和代码；经验沉淀后删除 `DISCOVERY.md`，不提交到 Git
- 正式文档直接吸收提炼后的结论，不引用临时的 `DISCOVERY.md`
