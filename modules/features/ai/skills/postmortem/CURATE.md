# 整理存量尸检

目标：每份留下的报告都满足 `SKILL.md` 的准入，其余的教训迁到更近的落点。

## 盘点

逐份读完，不凭标题判断。每份记四项：

- 症状：报错原文或用户可见现象
- 根因：是否仍成立，涉及的组件是否还在
- 护栏现状：护栏栏位写的路径、告警、命令，逐个 `ls` 或 `grep` 确认存在
- 同类：与哪几份共享症状或根因

## 分类

每份只归一类，按表自上而下取第一个命中的：

| 类别 | 判据 | 处置 |
| --- | --- | --- |
| 过时 | 组件已移除，或行为已被后续改动改变 | 删除 |
| 已落地 | 教训已被代码、配置、CI 或告警强制 | 删除，提交信息记编号与落点 |
| 同类 | 与另一份共享症状和根因 | 合并为一份，其余删除 |
| 排查剧本 | 只属于某个组件，价值在「症状到处理」 | 并入该组件运维文档的故障模式小节，再删除原报告 |
| 保留 | 通用、根因不显然、护栏落不进代码 | 压缩成 `SKILL.md` 的格式 |

「已落地」要求在代码里看到护栏，只在报告里声称护栏存在不算。

## 执行

1. 先并入，再删除：删除前确认该报告的『排查陷阱』已迁到落点
2. 保留的报告压缩成一页，补『症状关键词』
3. 全仓搜索被删文件名与序号，修正 README、文档、`AGENTS.md`、代码注释里的链接
4. 序号不重排，已删序号不复用
5. README 重写为症状表

## 交付

一个 PR。提交信息或 PR 正文给出去向表，供审查：

```txt
| 编号 | 处置 | 落点 |
| --- | --- | --- |
| 005 | 排查剧本 | docs/18-crowdsec.md 故障模式 |
| 012 | 已落地 | k8s/.../xxx.yaml |
| 019 | 保留 | 压缩 |
```

完成标准，全部可检查：

- 每份报告都有去向表中的一行
- `ls postmortems/*.md` 去掉 README 后的文件数，等于 README 症状表的行数
- 被删文件名在仓库里搜索无结果
- 每份保留报告含『症状关键词』与指向落地物的『护栏』
