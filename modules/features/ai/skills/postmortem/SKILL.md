## 准入

尸检的产物是护栏：阻止同类事故再发生的检查、告警、默认值或规则。三条同时成立才写：

1. 根因不显然：排查绕过弯路，或最初假设是错的
2. 会复发
3. 护栏落不进代码：lint、CI、测试、告警、默认值都覆盖不了

不写时的去处：

- 护栏能落进代码：改代码，教训写进提交信息
- 过程与证据：留在 issue 或 PR
- 同类症状已有报告或运维文档：更新那一处

写前读 `postmortems/README.md` 的症状表，找同类。

## 存放与命名

默认存放在项目根目录的 `postmortems/`。

文件名格式为 `序号-简短标题.md`：

- 序号为三位递增，取目录与 git 历史中出现过的最大序号加一，已删除的序号不复用
  ```bash
  git log --all --name-only --format= -- postmortems | grep -o '[0-9]\{3\}-' | sort -u | tail -1
  ```
- 标题使用小写英文和短横线，描述问题对象与核心错误，不使用空格、中文或特殊符号

## 格式

一页以内。时间线与完整日志链接 issue 或 PR，不入文。

```txt
# 标题

**日期**: YYYY-MM-DD
**症状关键词**: 报错原文、用户可见现象，3 到 6 个，用于检索
**影响**:

## 症状
<!-- 最小复现命令 + 关键报错 -->

## 根因
<!-- 错误假设 / 实际约束 / 缺失检查点 -->

## 排查陷阱
<!-- 走偏的路径，以及分辨真假方向的命令；没走偏则整节省略 -->

## 修复
<!-- 恢复步骤与以后的正确做法 -->

## 护栏
<!-- 可执行规则，并指向已落地的文件、告警或命令 -->
```

写完对照：

- [ ] 症状关键词含报错原文，凭症状能命中
- [ ] 根因区分错误假设与实际约束，不复述症状
- [ ] 护栏每条可执行，并指向已落地的文件、告警或命令
  - 坏例：`注意检查依赖版本`
  - 好例：`升级依赖前跑 nix eval + just bd，见 justfile 的 check 任务`
- [ ] README 症状表新增一行，序号不冲突

## README 格式

症状表，按组件排序：

```txt
# Postmortems

| 症状关键词 | 组件 | 报告 |
| --- | --- | --- |
| `crashloop`、`invalid duration` | etcd | [021](./021-example.md) |
```

## 整理存量

用户要求整理、合并或清理已有尸检，或 README 已无法按症状扫读时，读 [CURATE.md](CURATE.md)。
