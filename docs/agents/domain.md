# 领域文档

## 布局

本仓库采用单一上下文：

- `CONTEXT.md`：全仓库共享领域知识；
- `docs/adr/`：架构决策记录。

## `CONTEXT.md`

记录理解当前业务和架构所需的稳定知识：

- 领域术语及精确定义；
- 核心实体及其关系；
- 重要不变量；
- 系统边界；
- 已知但尚未解决的领域问题。

不要把实现细节、临时任务状态或单次故障写入领域文档。

## 架构决策记录

架构决策记录放在 `docs/adr/`，用于记录重要且持久的技术决策：

- 背景与约束；
- 最终决策；
- 考虑过的替代方案；
- 影响与代价。

文件名使用：

`NNNN-简短名称.md`

## 使用规则

- 讨论领域术语、边界或架构决策前，先读取 `CONTEXT.md`。
- 新决策与现有记录冲突时，先指出冲突，不静默覆盖。
- 领域模型变化时更新 `CONTEXT.md`。
- 已被替代的架构决策保留原文，并明确标记替代关系。
