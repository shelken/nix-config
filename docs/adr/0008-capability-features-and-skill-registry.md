# ai 按能力拆成独立功能

日期 2026-11-14

`ai` 原先按实现机制拆文件，一个能力散落在多个目录，主机也只能整体导入全部 `ai` 配置。现在只在工作站需要的能力拆为独立功能，每个目录内聚该能力的命令、应用、沙箱桩与 skill，`ai` 本体只保留所有运行 agent 的机器共用的运行时

## 规则

- 拆分判据为执行节点沙箱内的 agent 是否用得到。用不到的能力必须拆成独立功能并按 ADR 0004 声明角色，用得到的必须留在 `ai` 本体
- 只在宿主执行的命令必须由所属功能声明 `shelken.dev.sandbox.hostCommands`，不得集中堆在统一目录
- `modules/features/ai/skills/` 必须只放所有导入 `ai` 的机器共用的本地 skill，能力专属 skill 必须放在该能力目录下并经 ADR 0009 的统一入口登记

## 考虑过的替代方案

- 拆成 `ai` 与 `ai-desk` 两个大桶。桶内仍按机制分文件，单一能力依旧分散
- 把所有 skill 留在 `skills/`。非工作站节点会部署找不到对应命令的 skill
- 给 `ai` 各项增加 `enable` 开关。违背 ADR 0004 放弃开关组合的决定
