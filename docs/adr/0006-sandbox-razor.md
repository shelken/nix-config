# 0006 沙箱剃刀：删除附加 VM、待升级与破坏性 sync

日期: 2026-10-24
状态: Accepted
关联: 推翻 [ADR 0002](0002-single-main-vm-execution-context.md) 决策 4 后半句与决策 6；推翻 [ADR 0003](0003-shared-tool-single-declaration.md) 决策 9 中「沙箱手装插件下次 sync 消失」；sync 规则见 [ADR 0005](0005-shared-mise-install-layer.md)

## 背景

按 ADR 0002–0004 实现后，宿主 CLI 增长到约 1300 行，四轮审查的问题大多集中在三处：附加 VM 的并发生命周期（同时首次进入、最后退出撞上新进入、各自数据盘与 shims）、主 VM 忙时的待升级登记，以及 sync 的忙/闲两套模式及其与生命周期的竞态。日常使用方式是多个项目、多个 Agent 同时进同一台主 VM，这些机制都不在这条主路径上。

## 决策

1. **删除附加 VM**（推翻 0002 决策 6）。不再提供 `--dedicated`。所有执行上下文都在主 VM 内，多个项目、多个 Agent 共用这台 VM，隔离仍由执行上下文提供。
2. **删除待升级**（推翻 0002 决策 4 后半句）。能力上限变化时：主 VM 空闲则下一次启动自动重建；主 VM 仍有执行上下文则报错，给出运行中的上下文数，提示全部退出后重试。不登记、不在 `sb status` 显示待升级，也不逐项列出缺失能力。
3. **只用一把宿主生命周期锁**，只包住「检查上限指纹 → 必要时重建 → 启动 VM」。不做宿主侧预约；主 VM 忙闲只看 guest 内 launcher 的上下文登记。
4. **`sb sync` 永远只补缺**（推翻 0003 决策 9 的清理条款）。不区分忙闲，不删除、不重建插件依赖，因此 sync 不需要判断忙闲，也不需要生命周期锁。
5. **`sb status` 只报告缺失的 mise 工具**，不报告插件安装状态。

## 后果

失去的能力：

- 不能为单个项目单开一台 VM。主 VM 忙时若某项目需要超出当前上限的能力，只能等主 VM 空闲后重建。
- `sb status` 不显示待升级，也不显示插件是否装全；插件结果只看 `sb sync` 输出。
- 沙箱里手装的插件、或已从清单删除的插件不会被自动清掉，需要时用 `sb volume` 清理数据盘。
- 改了 `sb.yaml` 且两个 Agent 在同一两秒内启动时，后启动的上下文可能在启动阶段被重建打断，重新启动即可。
- 忙时 `sb sync` 可能在运行中的 OMP 底下更新插件文件；插件已加载进内存，风险低。
