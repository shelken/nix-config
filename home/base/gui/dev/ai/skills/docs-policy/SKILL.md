# 文档

## 内容与事实

- 能通过 CLI 或脚本快速获取的信息，记录获取命令，不保存容易过时的输出
- 代码已能表达的信息，指向对应代码文件，不在文档重复记录
- 面向 Agent 的文档说明事实与证据从哪里获取、如何获取或复现；已有脚本时直接引用，不堆积证据与枚举
- 问题记录使用「简短的问题 → 当前最佳解决方式」
- 日志型文档的旧结论被推翻时，用删除线标记，并补充新证据

## 组织与引用

- 新建文档前，先在项目内搜索相关关键词，寻找已有文档和合适位置
- 重复内容合并到一处，其他文档通过引用关联
- 重要文档应在 AGENTS.md 的「布局」中说明阅读场景；同目录文档超过三份时，用 README 聚合，再在 AGENTS.md 中引用该索引

## 隐私与路径

- 文档使用 slug 或变量表示路径前缀，不写绝对路径
- 不写真实手机号、邮箱、地址等隐私信息

## 语言与格式

- 中文少用状语，英文少用副词
- 无序列表项末尾不加标点，正文段落末尾默认不加句号
- 中文引号使用 `『』` 和 `「」`
- 不使用破折号，用逗号、句号或冒号衔接
- 避免 `不是X,而是Y`、`很直接`、`很具体` 这类生硬表达
- 多条命令放在代码块中；属于列表项的代码块缩进到该项内，例如

  ````md
  - 获取当前信息
    ```bash
    whoami
    ```
  ````

## 脚本与复现

- 编写脚本前遵循 Ponytail，先查找现有脚本；优先复用、合并、增强，避免散落的重复实现
- 复现脚本走最短路径，保持确定性与幂等性
- 每次编写脚本后，实际运行并确认输出符合预期
