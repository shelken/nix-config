# 文档

- 能够通过脚本/cli 实时动态且快速获取 的信息, 不要在文档进行记录, 而是在文档使用一条命令告诉如何获取, 这通常适用于那种经常变化的信息, 防止文档因为信息过时而腐败; 每次写出来的脚本, 务必自己验证进行确认和预期输出一致; 脚本实现前, 遵循ponytail原则, 其中复用脚本很重要, 找出已有脚本, 并思考如何复用, 避免创建更多散乱的脚本
- 如果文档很重要, 检查AGENTS.md中是否引用文档, 如果没有,应该在`## 目录`引用文档并说明在什么场景下阅读; 如果来源于同一个目录的文档超过三个, 那么聚合他们, 并在目录下创建README.md进行所有, 在AGENTS.md中进行聚合成一条, 并聚合阅读的场景和简单介绍
- 能够在代码中体现的信息, 也不要在文档进行记录, 而是指引去哪个代码文件名进行检查最新逻辑
- 当用户说保存plans时,通常将计划保存在`~/Code/docs/{project-name}/plans`下,名称格式`y-M-D-slug.md`
- 当项目没有对应 GitHub 仓库且需要保存 spec 时，保存到 `~/Code/docs/{project-name}/specs`，名称格式为 `y-M-D-slug.md`
- 文档记录问题(踩坑点和解决方式)时, 永远使用这个格式: `简短的说问题 -> 简短的目前最佳解决方式`
- 禁止在项目的任何文档中出现绝对路径, 使用slug指代前缀
- 无须列表的末尾永远不写标点符号; 文档中一段话的末尾默认不写句号
