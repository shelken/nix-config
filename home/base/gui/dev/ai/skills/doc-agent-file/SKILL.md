# AGENTS.md 的基本格式要求

```md
# {项目名}

{开头介绍项目 基本/核心 功能, 用一句话描述最核心}

## 布局

- `{重要目录/文件}`: {一句话简短重要说明}

## 约束

- {重要的行为规范}

```

- 以上格式为 Base(如果项目缺乏, 应该提醒用户)
- 通用性：当前范围下的其他代码也适用，且后续大概率会再次用到
- 只记录重要、非一次性的项目约定和约束; 如果代码已经可以说明问题, 不要记录到 AGENTS.md 中
- 不记录一次性任务背景、临时路径、普通 debug 过程
- **必须是项目相关的, 不要因为其他原因的错误也记录进项目中**
- 按就近原则选择涉及范围内最近的已存在 AGENTS.md；否则使用项目根目录 AGENTS.md
- 使用二级标题分组，标题下通常用无序列表
- `## 布局`: 一般不要精确到文件, 而是到目录; 重要文件/入口 可以例外
- `## 约束`(or `## 项目规范`): 负责描述日常开发行为规范, 必须由用户确认后才能进入, AGENT 只能提供建议; 当用户提出重要的有关项目的约束时,  展示建议写入的文本并询问是否记录; 建议时 **永远不要提出已经在代码体现的内容**; 建议内容必须是项目相关而非 **工具相关**
- 每次阅读到项目`AGENTS.md`时, 如果不符合格式要求, 在用户的任务结束前或者代码提交前询问用户是否调整, 并给出建议
