写前阅读 `docs-policy`。

## 何时写

阶段完成或准备结束本次工作时评估。没有真实事故，或只是不具备重复可能的小毛病时，不硬写尸检。

## 存放位置与命名

默认将尸检报告存放在项目根目录的 `postmortems/` 目录下。

文件名格式必须为 `序号-简短标题.md`，其中：

- 序号为三位递增序号，如 `001`、`002`
- 标题使用小写英文和短横线，简短描述问题对象与核心错误，不使用空格、中文或特殊符号

同时维护 `postmortems/README.md` 作为目录索引。写新报告前先读 README 取下一个序号；README 不存在则先创建。

## 尸检报告格式

使用以下结构：

```txt
# 标题

**日期**: YYYY-MM-DD
**影响**:
**发现人**:

## 问题
<!-- 发生了什么，影响了什么 -->

## 现象
<!-- 最小复现命令 + 关键报错 -->

## 根因
<!-- 错误假设 / 实际约束 / 缺失检查点 -->

## 修复
<!-- 当时怎么恢复 / 以后正确做法 -->

## 预防
<!-- 可执行规则，不写空话 -->

```

写完对照检查清单：

- [ ] 每个小节都有实际内容，无占位
- [ ] 根因区分了错误假设与实际约束，不复述现象
- [ ] 预防每条可执行，能写进 checklist 才算合格
  - 坏例：`注意检查依赖版本`
  - 好例：`升级依赖前先跑 nix eval + just bd 验证`
- [ ] README 已更新，序号递增且不冲突

## README 格式

保持简洁：

```txt
# Postmortems

- [001 · 示例标题](./001-example.md)
- [002 · 示例标题](./002-example.md)
```
