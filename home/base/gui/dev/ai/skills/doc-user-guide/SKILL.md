# 用户指南

## 编写前

- 先阅读已有用户指南，再询问用户本次要覆盖的内容
- 有 `docs-policy` 或 `waza-write` 时，阅读对应的文档与写作规范
- 按「当前代码 → 当前文档 → Git 历史」寻找答案，仍无法确定时才询问用户

## 内容与示例

- 内容简洁、易懂，以用户操作为主；可包含少量开发知识，不写大量开发文档或代码
- 根据实际实现描述核心功能，避免繁杂的功能罗列
- 展示核心配置示例，并用表格说明默认值与作用
- 需要本地配置示例时，向用户询问具体配置并调用 `grilling`；用户没有配置时，从代码中寻找路径
- 每份文档形成完整、连贯的操作流程，不留步骤缺口
- FAQ 先询问用户的疑惑，再按上述证据顺序寻找答案，记录到 `FAQ.md`

## 目录与索引

- 默认放在 `docs/user-guide/`，用同目录的 `README.md` 索引所有文档，表格包含「文件名与路径」和「简要说明」两列
- 使用 `00-<slug>.md` 命名，通常以 `00` 编写 quickstart；每个编号对应一个功能模块，按项目识别
- 在项目根 README 中链接 `docs/user-guide/README.md`，引导用户访问
