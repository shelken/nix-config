# 文档措辞中性化 SOP

把仓库文档里"逆向/抓包/爆破/绕过/防封号"类措辞改为中性合规描述,并在 `AGENTS.md` 声明项目定位。只调措辞,不删减/增加内容含义。

## 前置

- 只读检查: `git status --short` 看改动范围,确认哪些文档进 git(未跟踪文件如 `DISCOVERY.md`、`docs/reverse/` 也要处理)
- 先 grep 全库敏感词,建立清单再动手

## 措辞替换映射

| 原词 | 中性词 |
|---|---|
| 逆向 | 接口研究 / 分析 |
| 抓包 | 流量观测 |
| 爆破 | 排查 / 迭代 / 高频探测 |
| 绕过 | 不走 / 不匹配 / 不经过 |
| 解密(凭据/存储) | 读取 / 解析 / 密钥获取 |
| 防封号 | 遵守频率限制 |
| frida / hook(进程) | 调试器 / 观测 |
| 截获 | 观测 |
| 越狱 / 破解 / 反调试 | 移除(描述性文字直接删) |

## 保留项(技术名词,不改)

- 工具名: mitmproxy / relay / CDP / frida 安装名
- HTTP 术语: "注入头"、"patch 请求" 指接口行为
- 密码学术语: "已知明文攻击" 描述加密特性
- 文件名/路径: `cdp-hook.mjs`、`mitm-relay.js` 等

## 步骤

1. **AGENTS.md 定位声明**: 顶部加"项目定位"节,声明这是对目标服务**公开接口的兼容 provider**,只基于公开行为与对外接口,遵循公开使用方式与频控约束,不涉及任何规避或滥用
2. **全库扫描建清单**: grep 敏感词看分布与语境,先判断哪些是行为描述(要改)、哪些是工具名/术语/文件名(保留),再决定替换方式:
   - **脚本批量替换(大部分)**: 按映射表用 python 脚本一次替换多文件。每个替换带断言(`assert old in s`),防漏改;按文件分组,脚本里写明每组的替换对;先处理强敏感词(逆向/抓包/绕过),再处理弱词(解密→解码)
   - **edit 精确替换(少部分)**: 模板字符串含反引号、或需多行语义判断时,用 edit 逐处改,oldText 取最小唯一片段
3. **逐词核验**: grep 原敏感词确认 0 命中;再 grep 一遍替换词,人工过目是否变成语义不通的句子(如"待接口研究 CLI client_id"→改"待分析")
4. **保留项复核**: 确认工具名/术语/文件名没被误改;第三方依赖/解包副本(如 `node_modules`、`.venv`、`unpacked/` app 目录)不在范围内
5. **验证**: 无代码改动则无需跑测试;有代码改动先 `just verify`(或项目对应命令);改了 `src/` 注释至少 `tsc --noEmit` 确认没破坏

## 完成标准

- 强敏感词(逆向/抓包/爆破/绕过/frida/封号/越狱/破解/截获/防封)grep 全库 0 命中
- AGENTS.md 有公开接口兼容声明
- 语义未变: 每处替换都能通读

## 坑

- 只改措辞,不重写内容: 中性化 ≠ 删功能描述,读者仍能理解流程
- 未跟踪文件(本地笔记)同样要改: 用户说"整个仓库"时含它们;用 `git status --short` 的 `??` 列表对齐
- 全局 skill 与项目 skill 都在范围内,别只改一个
- 脚本替换后必须再 grep 一遍:**替换词可能残留敏感子串**(如"逆向"改"接口研究"后,原"待逆向"变成"待接口研究"仍别扭,需二次处理)
- 脚本替换要能重跑: 幂等(重复执行结果一致),这样核验时发现问题可直接改脚本重跑
