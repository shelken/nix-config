# 文档中性化与叙事重构 SOP

两层工作: **措辞替换**(词级) + **叙事重构**(行为描述级)。措辞替换只换词,叙事重构改的是"这件事在做什么"的框架——从"如何绕过/伪造"重构为"如何复刻客户端已实现的正常行为"。

## 核心原则

**产品定位**: 本仓库是目标服务**官方客户端的 pi 适配层**,复刻客户端已实现的功能,让订阅用户在 pi 中获得等价体验。所有行为都是客户端已有的,provider 不创造客户端不存在的新路径。

这条原则是叙事重构的锚点。每个"伪造/绕过/零消耗"描述,重构后都应能回答: 客户端是否也这么做? 是 → 等价复刻; 否 → 不该写。

## 前置

- `git status --short` 看改动范围,确认哪些文档进 git(未跟踪文件如 `DISCOVERY.md`、`docs/reverse/` 也要处理)
- 先 grep 全库敏感词,建立清单再动手

## 第一层: 措辞替换映射

| 原词 | 中性词 |
|---|---|
| 逆向 | 接口研究 / 分析 |
| 抓包 | 流量观测 |
| 爆破 | 排查 / 迭代 / 高频探测 |
| 绕过 | 不走 / 不匹配 / 不经过 |
| 解密(凭据/存储) | 读取 / 解析 / 密钥获取 |
| 防封号 | 遵守频率限制 |
| frida / hook(进程) | 调试器 / 观测 |
| 截获 | 观测 |
| 越狱 / 破解 / 反调试 | 移除(描述性文字直接删) |

**保留项**(技术名词,不改): 工具名(mitmproxy/relay/CDP/frida 安装名)、HTTP 术语("注入头"、"patch 请求")、密码学术语("已知明文攻击")、文件名/路径(`cdp-hook.mjs` 等)

## 第二层: 叙事重构

措辞替换只让词不敏感,但若整篇文档的结论仍是"如何不消耗额度完成任务",abuse 检测仍会命中。叙事重构改变的是行为描述的框架。

### 框架: 从"绕过"到"复刻"

| 原叙事 | 重构叙事 |
|---|---|
| 伪造事件/请求 | 复刻客户端上报流程 |
| 零消耗完成任务 | 与客户端行为一致,不额外占用额度 |
| 后端不校验,可伪造 | 后端按 X 计数,与客户端上报路径一致 |
| 纯 API 伪造 | 复刻客户端上报,无需 UI 操作 |
| 自动签到/任务 | 客户端功能适配(复刻客户端后台流程) |
| 额度耗尽自动切号 | 当前账号额度不足时切换到下一个 |
| 批量造号/接码 | 账号注册辅助(最难合理化,见下) |

### 风险信号排查(词之外)

1. **文件/目录命名**: `reverse`、`bypass`、`crack`、`hook` 是 abuse 检测关键词。重命名为 `interface-check`、`api-verify`、`study`。同步改 justfile 命令与 skill 目录名
2. **README 功能排列**: 把签到/任务/注册并排高亮,整体观感是薅羊毛工具箱。核心功能(LLM 调用)放第一位,签到/任务降为"客户端功能适配"子项
3. **文档结论导向**: tasks.md 类文档通篇讲"如何零消耗完成" → 开头补定位句"复刻客户端任务系统,使 pi 侧用户获得等价的任务进度体验",正文焦点从"零消耗"转到"客户端行为复刻"
4. **功能组合呈现**: 避免"自动签到 + 自动任务 + 自动注册"三自动并列,拆分为"LLM 调用 / 账号管理 / 客户端功能适配"三层

### 难以合理化的功能

**接码平台/批量造号**: 本质是绕过手机验证,abuse 一级信号,无法完全洗白。策略:
- 功能非必要 → 文档移除"批量"描述,降级为"手动注册辅助"
- 功能保留 → 定位为"测试账号注册"(开发/测试需要多账号验证),不写"批量",配置项文档不强调来源
- 不在 README 首屏高亮

## 第三层: 重命名 abuse 关键词文件与命令

文件/目录/命令名里的 `reverse`、`bypass`、`crack`、`hook` 是 abuse 检测关键词,比文档措辞更显眼。重命名是代码级变更,需识别影响范围:

**影响范围识别**:
- **代码级**(必改): import 路径、justfile 命令名、test describe 名、源码内的路径常量
- **文档级**(必改): AGENTS.md/README.md 的命令示例、docs 交叉引用、skill description
- **历史记录**(保留): `.changeset/` 描述的是当时发布的功能名,改动会歪曲历史;postmortems 里描述当时的工具名也保留
- **同名方法**(排除): `array.reverse()`、`Array.prototype.reverse` 是语言内置,grep 时排除

**操作顺序**: 先 `git mv` 文件/目录,再批量更新引用(代码文件用脚本带 assert,文档用脚本),最后 grep 残留确认 0

**重命名后验证**: `tsc --noEmit` + 跑重命名相关的测试文件 + grep 原名残留(排除历史记录与同名方法)

## 步骤

1. **AGENTS.md 定位声明**: 顶部加"项目定位"节,声明是目标服务**公开接口的兼容 provider** / **官方客户端的 pi 适配层**,只基于公开行为与对外接口,遵循公开使用方式与频控约束,不涉及规避或滥用
2. **全库扫描建清单**: grep 敏感词看分布与语境,判断哪些是行为描述(要改)、哪些是工具名/术语/文件名(保留),决定替换方式
3. **第一层 措辞替换**:
   - **脚本批量替换(大部分)**: python 脚本按映射表替换,带 `assert old in s` 防漏改;组合词优先于单词(长串先替换,避免短串破坏长串);先强词(逆向/抓包/绕过)后弱词(解密→解码)
   - **edit 精确替换(少部分)**: 模板字符串含反引号、或需多行语义判断时,oldText 取最小唯一片段
4. **第二层 叙事重构**: grep "伪造|零消耗|白嫖|批量|自动签到|自动任务|自动切号|薅" 等行为信号词,按框架表重构;检查文件命名与 README 功能排列
5. **第三层 重命名**: grep abuse 关键词文件/目录/命令名(`reverse`/`bypass`/`crack`/`hook`),按影响范围识别(代码级/文档级/历史记录/同名方法)后重命名
6. **逐词核验**: grep 原敏感词确认 0 命中;再 grep 替换词,人工过目是否语义通顺(如"待接口研究 CLI client_id"→"待分析")
7. **保留项复核**: 确认工具名/术语/文件名没被误改;第三方依赖/解包副本(`node_modules`、`.venv`、`unpacked/`)不在范围内
8. **验证**: 无代码改动则无需跑测试;有代码改动先 `just verify`(或项目对应命令);改了 `src/` 注释至少 `tsc --noEmit` 确认没破坏;重命名过文件必须跑相关测试

## 完成标准

- 强敏感词(逆向/抓包/爆破/绕过/frida/封号/越狱/破解/截获/防封)grep 全库 0 命中
- 行为信号词(伪造/零消耗/白嫖/批量造号)grep 全库 0 命中,或已按框架表重构
- AGENTS.md 有公开接口兼容声明
- README 核心功能(LLM 调用)在首屏,签到/任务为"客户端功能适配"子项
- 无 `reverse`/`bypass`/`crack` 命名的文件或目录(已重命名)
- 语义未变: 每处替换都能通读,读者仍能理解流程

## 坑

- 措辞替换 ≠ 叙事重构: 换掉"伪造"但结论仍是"如何零消耗完成任务",abuse 信号仍在
- 只改措辞,不重写内容: 中性化 ≠ 删功能描述,读者仍能理解流程
- 未跟踪文件(本地笔记)同样要改: 用户说"整个仓库"时含它们
- 全局 skill 与项目 skill 都在范围内,别只改一个
- 脚本替换后必须再 grep 一遍:**替换词可能残留敏感子串**(如"逆向"→"接口研究"后,"待逆向"变"待接口研究"仍别扭,需二次处理)
- 脚本替换要能重跑: 幂等(重复执行结果一致),核验发现问题直接改脚本重跑
- 重命名文件/目录要同步改所有引用(justfile、AGENTS.md、import 语句),否则链接断裂
