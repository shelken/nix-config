# Capture 参考

本文件为 `capture` 模式的完整流程与输出格式。共用规则（候选知识准入、冲突裁决、安全边界）见 `SKILL.md`。

用户显式调用 `capture` 即代表允许写入（`AGENTS.md` 除外，仍只提供建议并经用户确认）；证据、目标或作用域有歧义时，最多询问 1 至 3 个关键问题。

## 写入前检查

1. 收集至少一条历史或当前 Session 证据
2. 收集至少一条当前证据（代码、Git、测试、运行结果或有效文档）
3. 搜索支持和反向记录，确认没有未解决冲突
4. 检查现有代码、自动化、最近 AGENTS、上层 AGENTS、相关 Skill、ADR 和 README
5. 完全相同则不写；只是补充边界时更新原条目；作用域错误时移动或拆分；冲突未解决时停止写入

## 载体路由

按以下顺序判断：

1. 可执行约束：代码、类型、schema、测试、lint、CI 或脚本
2. Agent 必须反复遵守的项目规则：最近作用域的 `AGENTS.md`
3. 包含工具、步骤和判断条件的重复工作流：项目 Skill
4. 重要设计决策、领域术语和取舍：项目已有 ADR/决策文档，必要时使用 `domain-modeling`
5. 高影响事故、复杂故障和根因：项目已有 Postmortem 约定，必要时使用 `postmortem`
6. 用户或贡献者需要了解的稳定行为：README 或普通项目文档

如果更强的可执行约束超出当前任务范围，只提出建议并等待用户确认，不要退而求其次写成 AGENTS 提醒。

## 各载体的写入约束

优先遵循项目已有目录、命名、编号和 frontmatter。AGENTS、项目 Skill、README、普通文档和自动化只保留当前事实；过时内容直接更新或删除。

### AGENTS.md

- 写作格式与约束读取 `doc-agent-file`（SSOT）；仅提供修改建议，不直接编辑
- 使用被影响代码路径最近的已存在文件；未经明确要求不新建

### Skill

- 必须与项目强相关；项目专属流程不写入全局 Skill
- 使用项目已有 Skill 目录；编写前读取已有 Skill 风格并模仿，语言精简凝练
- 写 skill 前先读取 `writing-for-agents`，缺失时提醒且不做记录
- 只记录可复用流程，不记录单次错误；踩坑点只有以后会重复且重要才记录

### ADR

- 没有既有目录时，首次创建前询问用户
- 状态使用 Proposed、Accepted、Superseded、Rejected；旧 ADR 被替代时保留原背景并链接新 ADR

### Postmortem

- 写尸检前先读取 `postmortem`，缺失时提醒且不做记录
- 小修小补不记录；重点记录重大错误、重复错误、高影响事故
- 用户未主动要求时只建议、不直接写入，且只有影响范围明显较大时才建议
- 没有既有目录时，首次创建前询问用户
- 保留历史；后续发现错误时追加勘误，不静默改写事故经过

## 输出格式

```text
沉淀内容：
历史证据：
当前证据：
最终载体：
修改文件：
验证方式：
未解决冲突：
```
