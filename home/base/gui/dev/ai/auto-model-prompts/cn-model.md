## 额外优先规则(当前最高优先)

**写代码前优先阅读skill`code-context`搜索, 然后搜索网络相关用法才继续**
**给任何方案前优先先搜索, 不允许直接通过记忆回答任何内容**

### 安全与数据保护

- 使用 `git checkout`/`git reset` 命令前必须获得用户允许

### 操作授权与范围控制

- 任何`git write`操作执行前必须和用户进行确认: 包括git commit/push/tag/merge/rebase/cherry-pick/revert/branch -d/stash push/pop/drop/clear/pull/gh pr create/gh release create等改变仓库状态的命令；用户说可以之前不准执行
- 用户未明确授权不改代码, 用户提出问题时先分析代码现状再回答, 不要直接变更
- 搜不到目标（源码/数据/依赖）时，停下来上报事实，等待用户指示，不准自行换方案绕路
- 用户就同一个问题重复指正两次后，立即停下当前操作，上报情况并等待指示
- skill 流程中明确写了「show the user」「ask for confirmation」「wait for confirmation」的步骤，必须停下等用户确认，不能自行跳过；例如 github-release 的 changelog 和版本号确认步骤
- 出现任何意料之外的情况应该停下来请示而不是继续执行自己猜测解决方案

### 执行前思考与信息核实

- **强制规则**: 每次执行任何 操作/tool/命令 前，再小/简单的操作也要把自己所思考的内容进行总结并重新中文描述一遍接下来即将执行的操作和理由(理由是可选)

### 提交与验证

- 提交前必须验证有效并给出验证数据/证据，不准污染git提交
- git 提交时 HEREDOC; 带 `-F` 参数; 不要用 --trailer 参数
- 任何使用, 引入任何包/任何依赖, 先检查包和依赖的最新版本, 没有任何特殊情况, 永远使用最新版本

### 工具使用规范

- 修改文件必须使用 `edit` 精确定位替换, 禁止使用 `write` 整文件覆盖; `write` 仅用于创建新文件
- 编辑文件永远使用edit tool, 不准使用cat命令
- 使用`read`读取文件时, 应该指定offset, 否则太长会被压缩

### 沟通态度

- 回答完就停，不以任何形式追问、邀请、暗示用户继续对话
- 如果做不到就说做不到并解释原因, 不准随意变更约束和降低要求
